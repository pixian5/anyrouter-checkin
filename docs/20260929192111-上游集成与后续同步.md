# 上游集成与后续同步记录

> 后续维护策略修正：本地定制以外挂补丁维护，不直接修改上游已有文件；详情见本文件末尾的“外挂式修正”。

## 背景与安全边界

- 本地原分支：`main`，提交 `fb69050`，跟踪 GitCode `origin/main`。
- 上游：GitHub `millylee/anyrouter-check-in`，默认分支 `main`。
- 上游本次基线：`3b16662142c68703ea3e79c77c06a8cf6bba7990`（上游 HEAD）。
- 两边历史没有共同祖先：本地侧有 10 条独有提交，上游侧有 150 条独有提交。因此普通合并无法建立共同基线。
- 为不触碰原 `main`，在隔离工作树 `/Users/x/.codex/worktrees/upstream-sync/aicheckin` 新建 `codex/upstream-sync`，只在该分支执行首次整合。

首次合并使用：

```bash
git merge --no-commit --no-ff --allow-unrelated-histories upstream/main
```

解决冲突并提交后，上游历史成为集成分支的祖先。后续同步可使用常规 `git merge --no-ff upstream/main`，而不再使用 `--allow-unrelated-histories`。

## 首次历史接入

首次使用 `--allow-unrelated-histories` 将本地源码快照历史和上游历史连接起来。这个合并提交保留了原 `main` 为第一父提交、上游 `main` 为第二父提交。随后按本地的外挂式维护要求，恢复了上游已有文件原文，将需保留的本地配置与操作模板迁入 `deploy/`。

## 外挂式修正

- 根目录 `.env.example`、`.gitignore`、`pyproject.toml`、`uv.lock`、上游 workflow 与 `scripts/setup_mihomo_proxy.sh` 恢复为 `upstream/main` 原文。
- 旧 `ACCOUNT_N` 示例移到 `deploy/.env.legacy.example`；Pixian Actions workflow 模板移到 `deploy/workflows/pixian-checkin.yml`，不会被 GitHub 自动加载；镜像优先的 Mihomo 脚本移到 `deploy/setup_mihomo_proxy.sh`。
- 本地日志、锁、状态数据库和含测试凭据的临时脚本忽略规则由 `deploy/install-git-excludes.sh` 写入 clone 的 `.git/info/exclude`；两种本地安装脚本都会调用它。
- README 中只保留全局工程要求的进度/计划区块；`verify_upstream_unchanged.sh` 会规范化移除该区块后与上游 README 比较。

本地 `pixian_overlay/`、systemd unit、daemon、审计数据库和定制测试均继续保留。未来上游同步后必须先运行 `scripts/verify_upstream_merged.sh` 与 `scripts/verify_upstream_unchanged.sh`。

## 一并修正的验证问题

全量测试初次运行发现两条已有测试与当前实现不符，且在未修改的原 `main` 工作树上复现：浏览器 fetch 参数现在是包含 `path` 和 `headers` 的对象；WAF cookie 获取不完整时会跳过 httpx 并回退浏览器内 fetch。相应更新测试断言并加入回退路径验证。另修正已有 Ruff/MyPy 错误，并将 Node 求解器临时文件移入私有临时目录，显式使用解析到的 Node 可执行路径、参数数组及 `shell=False`。
