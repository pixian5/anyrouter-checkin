# 上游集成与后续同步记录

## 背景与安全边界

- 本地原分支：`main`，提交 `fb69050`，跟踪 GitCode `origin/main`。
- 上游：GitHub `millylee/anyrouter-check-in`，默认分支 `main`。
- 上游本次基线：`3b16662142c68703ea3e79c77c06a8cf6bba7990`（上游 HEAD）。
- 两边历史没有共同祖先：本地侧有 10 条独有提交，上游侧有 150 条独有提交。因此普通合并无法建立共同基线。
- 为不触碰原 `main`，在隔离工作树 `/Users/x/.codex/worktrees/upstream-sync/aicheckin` 新建 `codex/upstream-sync`，只在该分支执行首次整合。

首次合并使用：

```bash
git merge --no-commit --no-ff --allow-unrelated-histories upstream/main
```

解决冲突并提交后，上游历史成为集成分支的祖先。后续同步可使用常规 `git merge --no-ff upstream/main`，而不再使用 `--allow-unrelated-histories`。

## 冲突处理

- `.env.example`：采用上游 `ANYROUTER_ACCOUNTS` 示例，同时保留旧入口 `scripts/aicheckin.py` 所需 `ACCOUNT_N` 格式的注释示例。

- `.gitignore`：保留本地日志、锁、状态数据库和敏感测试脚本忽略规则，并保留上游规则。
- `.pre-commit-config.yaml`、`CONTRIBUTING.md`：采用上游当前版本。
- `scripts/setup_mihomo_proxy.sh`：保留国内镜像优先路径，并追加上游官方源作为最后回退。
- `.venv`、`.env` 等仍不纳入版本控制。

合并前逐树比较发现，当前共享的主要签到实现与本次上游树一致；差异主要集中在上述配置文件和本地部署/外挂文件。当前分支保留本地部署脚本与 `pixian_overlay`，并且允许在集成分支直接修改上游代码；后续通过 Git 合并显式解决冲突。

## 一并修正的验证问题

全量测试初次运行发现两条已有测试与当前实现不符，且在未修改的原 `main` 工作树上复现：浏览器 fetch 参数现在是包含 `path` 和 `headers` 的对象；WAF cookie 获取不完整时会跳过 httpx 并回退浏览器内 fetch。相应更新测试断言并加入回退路径验证。另修正已有 Ruff/MyPy 错误，并将 Node 求解器临时文件移入私有临时目录，显式使用解析到的 Node 可执行路径、参数数组及 `shell=False`。
